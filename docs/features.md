# 기능과 플랫폼 연결

Legacy는 기존 ZUKU의 계정·콘텐츠·게시글뿐 아니라 공개 URL도 공유한다. 기존 주소로 접속한 구형 브라우저에는 클래식 화면을 자동 선택하고 모던 브라우저의 처리는 유지한다. `/legacy`는 내부 구현·디버깅용이며 일반 이용자의 별도 진입 경로가 아니다.

이번 구현은 아래의 문서·양식 중심 기능을 제공하며, 전체 모던 클라이언트와 동일한 재생·제작·보안 기능이 모두 구현되었다는 뜻은 아니다.

‘보호된 연결’은 검증된 HTTPS 또는 같은 기기의 신뢰된 TLS companion을 뜻한다. 원격 HTTP에서는 공개 열람만 가능하다. 계정 기능에는 기존 모던 로그인에서의 기기 연결 승인이 추가로 필요하다.

| 기능 | 현재 Legacy에서 제공 | 조건·제약 |
| --- | --- | --- |
| 전체·Hype·Swipe·Jump·Vive·Vine 피드 | 제목, 설명, 창작자, 통계, 페이지 이동 | 기존 API가 반환하는 공개·권한 범위. 페이지당 12개 |
| 키워드 검색 | 기존 통합 검색 결과와 페이지 이동 | semantic search나 별도 검색 index를 만들지 않음 |
| 콘텐츠 상세 | 설명, 미디어·대표 이미지의 HTTPS 링크, 댓글 | 모던 플레이어와 동일한 재생 보장은 없음 |
| 창작자 프로필 | 이름, handle, 소개, 일부 통계 | 팔로우·프로필 수정 UI는 미구현 |
| Thread 읽기 | 게시글 목록, 대화와 답글, cursor 기반 이동 | 자동 갱신·무한 스크롤 없음 |
| Thread 작성·답글 | 일반 HTML form, 최대 280자 | 보호된 연결·연결된 계정·유효 CSRF 필요 |
| 게시글 좋아요·취소 | 기존 POST/DELETE API | 보호된 연결·계정 필요 |
| 콘텐츠 좋아요·보관함 추가/해제 | 기존 toggle API | 보호된 연결·계정 필요 |
| 콘텐츠 댓글 | 댓글 목록과 최대 1,000자 작성 form | 작성은 보호된 연결·계정 필요. 중첩 답글 UI는 미구현 |
| 내 보관함·내 계정 | 기존 계정의 목록·계정 요약 | 연결 세션 최대 15분, 자동 refresh 없음 |
| 화면 설정 | 기본 화면 / URL에 유지되는 텍스트 모드 | 텍스트 모드는 JS와 그래픽 효과를 포함하지 않음 |
| NeonUX-LC | DOM 기본 화면, 선택적 canvas·VML 장식 | 기기 기능과 정책에 따라 DOM fallback |

공개 `/`는 홈, `/community`와 `/community/:id`는 Thread이며 상품 채널·검색·콘텐츠와 `/profile/:handle`도 기존 공개 경로를 사용한다. 보호된 연결에서는 `/login`이 계정 연결, `/profile`이 내 계정이다. 평문 HTTP에서는 계정·보관함·메시지와 쓰기 양식을 숨기고 해당 진입점을 404로 처리한다. 내부 쓰기 action과 자산 경로가 `/legacy`에 있어도 페이지를 읽기 위해 사용자가 그 주소를 따로 선택할 필요는 없다.

## 모던 환경에서 이어서 하는 기능

| 기능 | 현재 연결 방식 | Legacy 내부에서 하지 않는 일 |
| --- | --- | --- |
| Hype·Swipe 영상, Vine 음악 | HTTPS 미디어 파일 또는 모던 플레이어 링크 | codec 이식, transcoding, DRM 우회, 미디어 프록시 |
| Vive의 완전한 읽기 경험 | 피드·소개·댓글에서 모던 콘텐츠로 이동 | 전용 장편 reader·모든 본문 타입 렌더러 구현 |
| Jump 게임 실행 | 소개·콘텐츠에서 모던 환경으로 이동 | WebGL·게임 엔진·저작 도구의 구형 브라우저 재구현 |
| DM·암호화 메시지 | 모던 `/messages`로 이동 | 서버 복호화, E2EE 제거, 평문 DM API 사용 |
| 비밀번호·패스키·CAPTCHA | 기존 모던 로그인 후 기기 연결 승인 | 인증 정책 우회, Legacy 전용 비밀번호 로그인 |
| 결제·wallet | 모던 플랫폼으로 이동 | 구형 페이지에서 결제 정보 수집 |
| Studio·업로드·관리·상세 계정 설정 | 모던 플랫폼 링크 | 파일 업로드, 제작·관리 도구의 기능 동등성 주장 |

모던 화면으로 이동하는 링크는 해당 기능을 구형 기기에서 실행 가능하게 만드는 변환기가 아니다. 대상 브라우저가 HTTPS·코덱·기능을 지원하지 않으면 다른 모던 기기에서 이용해야 한다. 브리지는 허용된 클래식 화면·계정 경로만 보호하고 외부 미디어·모던 화면의 전송을 대신하지 않는다.

## 연결과 조작 방식

보호된 클래식 화면에서 연결 코드를 만든 후, 모던 ZUKU의 승인 화면에서 코드를 확인하고 승인한다. 구형 화면에서는 ‘승인 완료 확인’을 눌러 연결을 마친다. 비밀번호나 access token을 오래된 브라우저에 붙여 넣는 절차는 없다. 평문 HTTP 화면은 연결 기능이나 보안 경고를 노출하지 않고 공개 기능만 보여 준다.

쓰기 form은 제출 후 일반 페이지 이동으로 결과를 보여준다. CSRF 토큰은 한 번 사용하면 바뀌므로 뒤로가기·다중 탭으로 오래된 form을 다시 제출하면 새 화면을 열어야 한다. 자동 재시도로 중복 게시를 만들지 않는다. upstream 오류나 권한 거부를 성공으로 표시하지 않는다.

독립 서버만 실행한 상태에서는 모던 승인 화면이 설치되지 않았을 수 있다. 제공된 Next 통합 예제를 기존 AuthVault에 연결하고 같은 handler/state를 사용해야 실제 계정 연결을 완료할 수 있다. 외부 모던 사이트가 이 저장소를 배포하지 않았다면 링크만으로 연동이 자동 완성되지 않는다.

기능을 추가할 때는 기존 API와 권한 정책을 먼저 재사용하고, 이 표에서 ‘현재 제공’, ‘모던 연결’, ‘미구현’을 갱신한다. 구형 클라이언트만의 별도 계정·콘텐츠·암호화 정책을 만드는 방향으로 확장하지 않는다. 자세한 경계는 [구조](architecture.md), [보안](security.md), [호환성](compatibility.md)에 정리했다.
